**Based on Release 2.2 brief (6 April 2026), Appendix B Level 7 marking criteria.**
**Source of truth:** `docs/PROJECT_BRIEF_COMPLETE.md` §10

This rubric is DELIBERATELY HARSH. Level 7 assessment expects autonomy, originality, and professional insight — not compliance. A "good undergraduate reflection" is a **low 60s** here. Distinctions (70+) require visible evidence of developed self-awareness and leadership.

### 1.4 PRESENTATION & PROFESSIONALISM (cross-cutting — influences all 3 criteria via Communication sub-score)

The D7 rubric has 3 criteria (Teamwork / Self-management / Insight) — but **how you present** your reflection directly affects the marker's reading of all three. Sloppy formatting signals sloppy thinking.

**Layout scored checkpoints:**

| Element | Requirement |
|---------|-------------|
| **Font size** | 10pt or 11pt body text. Never smaller. |
| **Line spacing** | `\linespread{1.05}` — tight but readable |
| **Margins** | 1.8–2 cm on all sides. Consistent. |
| **Section headings** | Visibly distinct, consistent style, bold |
| **Tables** | Compact but readable. `\small` minimum. Row spacing `1.05`. No touching borders. |
| **Paragraph breaks** | `parskip 0.3em` — visible but not wasteful |
| **Page balance** | Each page 85–95% filled. No orphans, no widows. No single-line tails. |
| **Visual hierarchy** | Headings > subheadings > body. Clear at a glance. |
| **Consistency** | Same font, same heading style, same table style throughout |
| **Rubric mapping table** | One compact table showing which question is answered where — assessor aid |

**Automatic flags:**
- ❌ >20% whitespace on any page → CAP 62 (wasted real estate)
- ❌ Walls of text with no breaks → CAP 62 (unreadable)
- ❌ Inconsistent heading styles → CAP 62 (unprofessional)
- ❌ Tables narrower than ¾ page → often wasted (reconsider layout)
- ❌ Orphan headings at page bottom → CAP 65
- ❌ Figures without captions → CAP 62 (if any figures used)
- ❌ References present but not cited in body → CAP 65

### 1.5 APPENDICES & REFERENCES (when used)

D7 is primarily a reflection — references and appendices are OPTIONAL. If used, they must earn their place:

**Appendices (optional, don't count toward 5/7-page limit):**
- Acceptable: self-evaluation matrix, development log timeline, named incident cross-reference table, tool/skill inventory
- NOT acceptable: padding with technical diagrams (that's D6 content), team photos, generic CV-style content
- Every appendix must be **referenced from the body** or it counts as padding → penalty
- Appendix formatting same quality as body

**References (if cited):**
- Cite only if genuinely load-bearing (e.g. a specific reflective practice framework like Gibbs/Schön, a named leadership theory, a published engineering practice you applied)
- **Every reference in the bibliography MUST be cited in the body** — unused refs = CAP 65
- Format: consistent style (biblatex preferred), numbered or author-year, not mixed
- Generic "I read about Scrum" without citation adds nothing — cut it
- 0–5 references is normal for D7. More looks performative.

**Scoring bonus for appropriate use:**
- +2: one well-chosen reference (e.g. Schön *The Reflective Practitioner*) that actually frames a personal insight
- +2: a 1-page compact appendix that provides evidence supporting body claims (e.g. development actions log with dates and outcomes)
- +0: references or appendices used without purpose — neutral at best

## 2. The 10 Required Questions (§10.1 of brief)

Every question is a checkpoint. Missing or weak answers lose marks.

### My role (3 questions)
- **1a** — Roles (explicit vs implicit), did they change? [3 marks]
- **1b** — What are you most proud of? [3 marks]
- **1c** — Focus differently in future? [3 marks]

### My team (3 questions)
- **2a** — Team structure, discussed explicitly? Changed? [3 marks]
- **2b** — Most impactful team-working elements? [3 marks]
- **2c** — What would you change next time? [3 marks]

### My impact (2 questions)
- **3a** — How did YOUR contributions drive the team? [4 marks]
- **3b** — Add/refocus in future? [3 marks]

### My support (2 questions)
- **4a** — What did others do that helped YOU? [3 marks]
- **4b** — What did YOU do that helped OTHERS? [4 marks]

**Total question coverage = 32 marks** (not the whole mark, just the question-coverage gate). Missing any question scores zero for that slot.

## 3. Scoring Algorithm

1. **Apply hard gates first** (§0). If any violated, cap the score.
2. **Score each criterion 0–100** per Appendix B descriptors.
3. **Average** (equal weights since brief doesn't state).
4. **Apply question-coverage penalty**: for each missing/weak question (§2), subtract marks.
5. **Apply evidence floor**: if fewer than 5 named specifics (people, dates, incidents, tools), **cap at 62**.

## 4. What Distinction (70+) Actually Looks Like

A 70+ D7 is NOT just well-written. It demonstrates:

1. **Named incidents** — specific things that happened, with dates/people/outcomes
2. **Conflict managed** — at least one disagreement you navigated (even mild)
3. **Autonomous initiative** — something YOU started without being asked
4. **Self-critical honesty** — genuine weaknesses with actions taken
5. **Feedback given to others** — specific feedback that changed their behaviour
6. **Self-development programme** — not "I learned X" but "I did A, B, C to address gap Y, result was Z"
7. **Changed thinking** — how the project changed your worldview/approach
8. **Leadership without title** — ways you led informally (proposing ideas, unblocking others)

**80+ adds:** creativity, responsiveness to teammates' individual interests, outstanding organisation.

## 5. Common Failure Modes (be ruthless checking for these)

1. **Team summary masquerading as reflection** — talking about "the team" more than "I"
2. **Self-praise without self-critique** — all positives
3. **Vague generalities** — "communication", "teamwork", "learning" without specifics
4. **Listing rather than reflecting** — bullet points of tasks instead of analysis
5. **Technical achievements reported as reflection** — "I built X" is D6 content, not D7
6. **Missing "what I'd do differently"** — no forward-looking growth
7. **No named teammates** — can't demonstrate team dynamics without naming them
8. **Quoting the brief back** — using brief language instead of personal voice
9. **Passive voice** — "it was decided that..." instead of "I proposed..."
10. **AI tone** — smooth, neutral, generic prose with no personality

## 6. DENSITY / PAGE UTILISATION (Communication criterion)

**Blank space is the enemy.** Presentation is a scored criterion. A page that's 40% whitespace wastes assessment real estate. Every cm² must earn its place.

### Staging strategy (WORKING DRAFT vs FINAL)

1. **Working draft — up to 7 pages allowed.** During iteration, we prioritise *content density and quality* over hitting 5 pages exactly. Get everything in first, then cut.
2. **Final submission — 5 pages hard.** After content is locked and every paragraph justified, we cut 2 pages by:
   - Merging overlapping paragraphs
   - Moving supporting detail to tables
   - Tightening bullets to single lines
   - Pulling out the weakest anecdote per section

### Density tactics (try and screenshot each)

- **Compact tables** — use `\small` or `\footnotesize`, `tabularx`, `p{}` columns with tight widths, `\arraystretch{1.05}` (not 1.2+)
- **Two-column subsections** — use `multicols` for lists that don't need full width (skills learned, tools used, etc.)
- **Sidenotes / margin annotations** — `marginpar` or `sidenotes` package for rubric tags (e.g. "1a", "2b") without eating line budget
- **Inline evidence markers** — `[commit 3d62e6a]`, `[session 2026-03-31]`, `[wk20]` instead of "(see Figure 2)"
- **Mini-headings as lead-ins** — `\textbf{My role.}` at the start of a paragraph saves a full line vs a heading
- **Reduced vertical spacing** — `\setlength{\parskip}{0.3em}`, `\titlespacing*{\section}{0pt}{0.6em}{0.3em}`
- **Table-based structure** for "what went well / even better if" — two-column compact table beats bullet lists
- **Condensed lists** — `enumitem` with `itemsep=0pt, topsep=2pt, partopsep=0pt`
- **Narrow margins** (within reason) — `geometry` with `top=1.8cm, bottom=1.8cm, left=2cm, right=2cm`
- **Compact rubric mapping table** — 1-line-per-question table mapping 10 questions → where answered
- **Inline named incidents** — `[Robin handoff, wk21]` rather than full incident descriptions

### Screenshot the drafts — iterate visually

After each rewrite:
1. Compile → PDF
2. Render each page to PNG (`pdftoppm -r 150 main.pdf page`)
3. Visually check: where's the whitespace? What's sparse? What's overcrowded?
4. Tweak table widths, paragraph breaks, `\small` / `\footnotesize` sizing
5. Re-compile, re-screenshot

Target: **every page 90%+ filled, no section orphans, no widow lines, balanced visual weight**.

### READABILITY FLOOR (hard constraint — don't over-compress)

Compact ≠ cramped. The assessor must be able to read comfortably. Follow these floors:

- **Body font size: 10pt or 11pt** — NEVER below 10pt for body text
- **Line spacing: `\linespread{1.05}`** — tight but clear. Never `\linespread{0.9}` or smaller.
- **Table font: `\small` (9pt) minimum** — `\footnotesize` only if absolutely necessary for edge cases
- **Paragraph spacing: `\parskip=0.3em`** — visible breathing room between paragraphs
- **Column gaps in `multicols`: `\columnsep=1em`** — don't touch column borders
- **Margins: `1.8cm–2cm`** — not less than 1.5cm or the page looks amateurish
- **Headings: clearly distinct from body** — use `\textbf{}` + `\large` for section headings, not just inline
- **No text touching table borders** — `@{\hspace{4pt}}` padding on tabularx columns if needed

**Rule of thumb:** if you squint at the page rendering from arm's length, you should still be able to distinguish paragraphs, headings, and table rows instantly. If it looks like a wall of text, it's too dense. If there's visible whitespace gaps, it's too sparse.

**Working observations from the verbatim text:**
- "What went well / even better if" is the **explicitly suggested framework** — use it structurally (e.g. as a table for each of the 4 headings)
