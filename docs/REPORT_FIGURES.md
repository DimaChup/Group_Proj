#### F2 -- Motion Blur vs Speed

**File:** `analysis/plot2_speed_vs_blur.png`

**Report section:** Vision System Design -- Motion Blur Analysis

### T8 -- NFZ Avoidance Approach Comparison

**Source:** `analysis/speed_blur_detection.md` Section 8; `docs/DESIGN_SUMMARY.md`

**Report section:** NFZ Avoidance -- Design Decision

| Property | REPEL (velocity push) | SLOW (velocity toward WP) | CARROT (DO_CHANGE_SPEED) |
|----------|:---:|:---:|:---:|
| Uses ArduCopter trajectory planner | No | No | **Yes** |
| Smooth movement | No (oscillation) | No (jitter) | **Yes** |
| Code complexity | Medium | High | **Low** |
| Controller conflict | Yes | Partial | **None** |
| Failsafe on command gap | Drift | Stop | **Continues to WP** |
| **Selected?** | No | No | **Yes** |

**Key point:** The carrot method delegates spatial reasoning to ArduCopter's trajectory planner, modifying only speed. Config: `NFZ_SLOW_ZONE_M = 20 m`, `NFZ_MIN_SPEED_MPS = 0.3 m/s`.

## HOW TO REGENERATE PLOTS

All plots can be regenerated from source data. No drone or SITL connection needed.

```bash
# Vision performance plots (F1--F5)
python analysis/vision_performance_plots.py

# Path optimization plots (F6--F11)
python analysis/path_optimization/optimize_path.py

# Dry-run pattern overlay (F18)
python main.py --dry-run
```

The training curves (F12--F15) are generated by Ultralytics during Colab training
and cannot be regenerated without re-running the training. The Pi benchmark and
blur/altitude data (F16, T5, T6) were collected on hardware and are stored as
results files in `pi_data/`.
